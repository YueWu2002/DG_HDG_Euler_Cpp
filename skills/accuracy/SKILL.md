先读根目录 `AGENTS.md`。以下路径均相对本项目根目录。

## 入口与数值协议

读取 `accuracy_test/{1d,2d}/convergence.py`、`scripts/experiment.py`、`scripts/provenance.py`，涉及提交时再读 `accuracy_test/{1d,2d}/submit.sh`、`scripts/submit_experiment.sh`、`scripts/submit_2d.sh` 和对应 `experiment*_job.sh`。数学口径查 `MATHEMATICS.md`；MFEM 对照源码在 `../mfem_euler2d_cpp`，本项目不链接 MFEM。

正式收敛测试使用 k=2、SSP-DIRK3、CFL=2、T=0.2，DG/HDG 配对，精确 block-Jacobi 右预条件 GMRES；Newton/线性容差均为 1e-12，restart=20、max-linear=1500、max-newton=30、HLL safety=1.1。1D 网格为 32、64、128、256、512；2D 为 N×N，N=32、64、128、256，alpha=45°。执行前核对脚本和配置实现，用户的新参数优先。

收敛测试必须按准则完成 Newton 求解，不使用测速的固定四次更新。空间和时间同步加密，保持 CFL、终止时刻、求积及求解设置一致。

## 提交与数据归属

- 每个网格单独一个 Slurm 任务，网格之间无 dependency、无需同一节点；一个任务保留该网格 DG/HDG 配对。提交路径必须真正把单网格参数传入驱动，不能仅改变任务名称。若入口仍扫描多个网格，先改造该入口再提交。
- 同批任务使用同一源码快照内容及参数，保存批次、网格和任务号映射。按每个网格的工作集和构建需要申请内存，留余量；精度并行运行的耗时不作为正式速度证据。
- Slurm 与本地输出均放在 `accuracy_test/running/<独立运行目录>/`。本地省略 `--output` 自动生成唯一目录；显式路径也必须在 running 下。Slurm 保留 `job_<id>/data/` 的既有输出布局。
- 保留命令、原始 CSV、日志、CPU、版本哈希及编译信息；使用共享 provenance 机制。已结束任务用 `scripts/archive_finished.py` 归档到顶层 results。旧路径中仍在运行的任务保持原位，不为目录整洁而搬移。

## 验收与汇总

1. 核对 Slurm 终态、退出码、完整 DG/HDG summary、`*_difference.csv`、命令与元数据。仅存在 iterations 或空 summary 不能算完成。`SUCCESS` 只证明对应驱动要求的网格完成；单网格 SUCCESS 不等于整个批次完成。
2. 核对实际终止时间、步数、min/max/mean dt、CFL、阶数、方法、求积、容差和源码版本。不同 CPU 允许并行，但分别记录，不能据此推断代码相同。
3. 按实际 N 排序，以 `log(e_old/e_new)/log(N_new/N_old)` 计算各守恒量阶数。1D 为 rho、momentum、energy；2D 为 rho、momentum_x、momentum_y、energy。误差必须有限且正；缺失值不补零。
4. 读取 `*_difference.csv` 和汇总中的分量差、joint_L2、max_nodal。各自精确解误差相近不能替代 DG/HDG 解差验证。
5. 批次后处理结果保存在所属运行目录，记录所有输入任务、版本、参数和路径。只有全部指定网格完成且可比时标记整批成功。

异常阶数先查完成状态、dt、初始化、物理可容许性、边界、求积、容差与残差定义，不通过改变协议追求预期阶数。历史缺失元数据标为未知；不删除宝贵 CSV 来掩盖不确定性，不编造数据。

## 运行目录与归档开发规范

- accuracy_test 与 speed_test 均在顶层使用 `running/` 和 `results/`：即 `accuracy_test/{running,results}/`、`speed_test/{running,results}/`。`1d/`、`2d/` 继续保存测试驱动和说明，不再分散保存新结果。
- 每次运行使用独立文件夹，名称带维数、时间戳和唯一后缀，例如 `running/2d_submission_<时间戳>_<唯一后缀>/`。排队和运行中的任务都放在 `running/`。
- 每次运行的文件夹必须完整包含其计算输出、后处理数据、CPU 型号、实际参数、代码版本及源码哈希、构建环境、任务状态等；保留现有 `job_<id>/data/` 输出布局，不额外新设计算输出目录。报告放在对应运行文件夹内，跨运行报告必须记录输入运行的身份。
- 任务结束后整体移到 `results/`，保持文件夹内部结构。成功、失败、取消均应归档并记录状态；不得把部分结果标为成功，不得覆盖已有运行目录。使用 `python3 scripts/archive_finished.py` 核对 Slurm 并归档；该命令应在任务结束后执行，而不是从运行中的批处理脚本内搬移自身目录。
- 已经运行或排队的旧任务属于过渡例外：保留原有路径，禁止搬移或修改其文件、源码快照和日志。待任务完全结束并确认没有其他任务仍依赖其路径后，再整理到顶层 `results/`。
- 历史数据按已知运行批次整理到 `results/<运行标识>/`；保留所有可用 CSV 和设备日志，无法恢复的 CPU、代码版本或原始输出必须明确标记为未知或缺失，不得伪造。不同独立运行不得因日期相同而混为一次运行。
- `.gitignore` 必须允许 CSV、设备/环境日志、命令、版本清单和追溯元数据纳入 Git。只忽略构建产物和重复源码快照等；Git 忽略规则不代表允许删除磁盘上的原始运行数据。
- 新增本地测试、Slurm 提交、后处理或报告入口时，必须遵循上述目录和归档约定，并更新相关文档引用。既有在运行任务使用的旧入口快照保持不动。
- accuracy 的 1D/2D 本地测试入口省略 `--output` 时，必须自动创建 `running/<维数>_local_<时间戳>_<唯一后缀>/`；显式输出路径也必须在对应 `running/` 内。Slurm 测试输出位于 `running/<提交目录>/job_<id>/data/`。不得直接在 `results/` 内启动计算。

## Slurm 提交入口开发规范

- 以后提交 1D/2D 收敛阶测试时，必须按独立网格算例拆分 Slurm 任务；每个 N 单独提交，不得让一个任务串行跑完整网格列表。DG/HDG 配对可保留在同一网格任务中，以统一该算例的参数和差异验证。
- 各网格任务独立排队、并行运行，不设置相互依赖，不要求同一节点，不使用节点绑定来限制并行。每个任务分别记录实际 CPU 和节点。
- 根据维数、网格规模、阶数、DG/HDG 工作集、精确 block-Jacobi 存储和构建需求估算内存，留出合理余量；不得将最大网格的内存申请机械地用于所有网格。根据实际峰值 RSS 调整后续申请。
- 每个任务在 `running/` 下拥有独立运行目录、源码版本、参数、设备信息及输出。各任务使用同一批次的源码和数值协议，保留批次标识及各网格任务号，防止混合不同版本结果。
- 后处理按实际 N 排序，仅对版本和数值协议一致且完成的相邻网格计算收敛阶。未完成网格保留为待计算，失败网格明确标识；只有全部要求的网格及 DG/HDG 校验完成后，才能标记整批成功。
- 当前已在运行的串行收敛测试保持不动；本规范适用于后续提交。提交入口改造时必须同步实现逐网格提交与批次汇总。
